# ServiceFlow 完整使用指南

## 1. 选择运行方式

| 方式 | 页面与入口 | 依赖及用途 |
|---|---|---|
| 本地 Compose | Nginx 80、API 8000 | Redis、Chroma、Prometheus；开发和完整功能验证 |
| 宿主机源码 | API 8000 | 自行启动 Redis/Chroma；便于断点与热更新 |
| Render 演示 | 同源 HTTPS 网关 | Key Value、嵌入式 Chroma；受限公开演示 |

首次启动见 [Windows 安装](../SETUP_WINDOWS.md)。本地未配置生产鉴权，勿直接映射到不可信公网。

## 2. 配置说明

| 配置 | 含义 |
|---|---|
| `DEEPSEEK_API_KEY` | 模型凭据，必填且保密 |
| `DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL` | 模型标识及 Anthropic 兼容服务地址 |
| `REDIS_URL` | 工作记忆连接，密码需与 Redis 一致 |
| `REDIS_PASSWORD` | 本地 Compose Redis 密码 |
| `CHROMA_HOST`、`CHROMA_PORT` | 独立向量服务地址；不可达时可能进入本地模式 |
| `CHROMA_PERSIST_DIRECTORY` | 本地嵌入式 Chroma 存储目录 |
| `SERVICEFLOW_SKILLS_DIR` | 业务规则目录 |
| `SERVICEFLOW_SKILLS_MAX_PROMPT_CHARS` | Skills 总字符预算，默认 5000 |
| `MONITOR_INTERVAL` | 监控采集间隔，默认 10 秒 |
| `PROMETHEUS_PORT` | 可选独立指标服务端口，默认 0 |
| `ALERT_WEBHOOK_URL` | 可选告警地址，可能涉及外部数据发送 |
| `EVAL_BASELINE_PATH` | 评测基线文件位置 |

DeepSeek 变量优先；旧 `ANTHROPIC_*` 仍有兼容路径。Skills 新前缀优先，旧 `ECHOMIND_SKILLS_*` 仅作为迁移兼容。不要把配置打印到公共日志，也不要提交 `.env`。

Compose 显式覆盖容器内 Redis/Chroma 地址。示例 Redis 密码仅用于本地演示；已有部署继续使用自己配置的密码，不需要因改名而轮换。部署到非可信网络前必须更换示例值并增加鉴权。

## 3. 启停与日志

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail 150 serviceflow
docker compose logs --tail 100 redis chromadb
docker compose restart serviceflow
docker compose down
```

重新构建应用不会自动清空数据库。更换 Compose project name 会改变命名卷前缀，应先确认已有数据位置。停止通常不需要 `down -v`，本手册不把删库作为常规排障步骤。

## 4. API 总览

以下是本地完整 API；公网网关只允许选定的聊天接口。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 应用状态，不等于模型调用已成功 |
| POST | `/chat` | 主对话，JSON 请求体 |
| GET | `/trace/tool/{request_id}` | 单请求工具轨迹 |
| GET | `/trace/tools?limit=20` | 最近轨迹 |
| POST | `/search?query=...&top_k=5` | 优化检索，query 是查询参数 |
| POST | `/knowledge/add` | 批量导入 JSON 文档 |
| POST | `/knowledge/upload` | multipart 文件导入 |
| GET | `/knowledge/stats` | 文档片段数 |
| GET | `/skills` | 规则摘要与解析错误 |
| POST | `/skills/reload` | 重新扫描规则 |
| GET | `/monitor` | 运行统计、建议和告警 |
| GET | `/metrics` | Prometheus 格式指标 |
| POST | `/eval/run` | 默认或自定义评测，产生模型费用 |

精确请求模型以本地 [Swagger](http://localhost:8000/docs) 及 `api/main.py` 为准。

## 5. 单轮和多轮聊天

```powershell
$body = @{
  message = '我的订单重复扣款，应该提供哪些信息？'
  user_id = 'guide-user'
  conv_id = 'guide-session'
} | ConvertTo-Json
$reply = Invoke-RestMethod -Method Post -Uri http://localhost:8000/chat -ContentType 'application/json' -Body $body
$reply | ConvertTo-Json -Depth 8
```

下一轮使用相同 `user_id` 和 `conv_id`，更换 message 即可。新会话更换 `conv_id`；不能通过更换用户 ID 冒充可信身份。

响应重点：

- `response`：最终回答。
- `intent`、`intent_group`、`entities`：识别结果。
- `primary_agent`、`supporting_agents`：主辅角色。
- `routing_reason`、`routing_confidence`：路由依据。
- `tools_used`、`knowledge_used`：工具使用情况，不是事实正确性保证。
- `request_id`：追踪入口。
- `latency_ms`：编排链路的计时，不是包含全部前后处理的 HTTP 端到端时延。

```powershell
Invoke-RestMethod "http://localhost:8000/trace/tool/$($reply.request_id)" | ConvertTo-Json -Depth 12
```

轨迹不是可无限保存的审计日志；进程重启、缓存淘汰后可能查不到。

## 6. 知识库导入与搜索

启动时若知识库为空，会添加六篇示例业务文档。所有政策、会员和配送说明都用于演示，并非真实承诺。

批量写入：

```powershell
$knowledge = @{
  documents = @(
    @{title='演示支持时间'; content='示例服务的人工支持时间为工作日 09:00 至 18:00；仅用于测试。'}
  )
} | ConvertTo-Json -Depth 4
Invoke-RestMethod -Method Post -Uri http://localhost:8000/knowledge/add -ContentType 'application/json' -Body $knowledge
```

文件导入与查询：

```powershell
curl.exe -X POST http://localhost:8000/knowledge/upload -F "file=@data/demo_docs/sample_knowledge.json"
curl.exe -X POST http://localhost:8000/knowledge/upload -F "file=@data/demo_docs/troubleshooting.md"
Invoke-RestMethod http://localhost:8000/knowledge/stats
Invoke-RestMethod -Method Post -Uri 'http://localhost:8000/search?query=支持时间&top_k=3'
```

JSON 文件是 `[{"title":"标题","content":"正文"}]` 数组，不是 `documents` 包装对象。上传大小上限为 10 MiB；当前接口会先读入内存，不是流式处理。优先使用 UTF-8 的 JSON、TXT 或 Markdown，未实现 PDF/Word 解析。

切片近似 500 字，不是固定 500 Token。当前导入使用 add，重复导入不等于受控更新；知识修改、删除、版本管理和缓存失效需要后续完善。

## 7. Skills 修改与验证

编辑 `skills/<场景>/SKILL.md`，检查角色、关键词和预算：

```powershell
Invoke-RestMethod -Method Post http://localhost:8000/skills/reload
Invoke-RestMethod http://localhost:8000/skills | ConvertTo-Json -Depth 8
```

确认错误列表及加载数量，再用固定问题验证行为。解析成功不表示所有规则都会进入提示词；必须命中匹配且未被字符预算截断。规则不应要求读取真实密码或执行未授权动作。

## 8. 记忆存储与检查

| 位置 | 内容 | 生命周期 |
|---|---|---|
| Redis | 近期消息与滚动摘要 | 默认 24 小时 TTL |
| Chroma `episodic` | 情景摘要和历史片段 | 按持久化部署保留，未实现完整保留策略 |
| Chroma `user_profile` | 同一用户的提炼画像 | 稳定 ID upsert，异步更新 |
| Chroma `knowledge_base` | 文档及片段 | 与会话独立 |

读取源码中的 key 构造函数和 collection 名称确认存储，不要在共享终端打印全部对话。需要检查数据库时使用测试用户、只读查询和受控输出。

情景检索过滤为用户与会话的 `$and`，跨会话补充也只允许同一用户；测试见 `tests/test_memory_retrieval.py`。过滤正确不代表已完成身份认证和全生命周期隐私管理。

画像后台任务存在延迟；服务重启可能中断任务。Redis 24 小时 TTL 不意味着 Chroma 中的个人数据也自动删除。

## 9. 监控与评测

```powershell
Invoke-RestMethod http://localhost:8000/monitor | ConvertTo-Json -Depth 8
Invoke-RestMethod -Method Post http://localhost:8000/eval/run | ConvertTo-Json -Depth 12
```

评测会多次调用模型，请在确认额度后执行。内置小样本只用于冒烟，不代表业务准确率。Judge 失败、网络错误和回退值必须单列，不能计为有效质量评分。

默认 `PROMETHEUS_PORT=0` 时，业务指标注册不完整，不能仅根据 `/metrics` 页面声称完整监控已启用。当前告警阈值也未适配所有 LLM 延迟场景，需区分慢响应、冷启动和失败。

详见[评测与优化](评测与优化.md)。

## 10. 常见问题

| 问题 | 排查顺序 |
|---|---|
| Docker npipe 报错 | Docker Desktop 引擎、context、WSL，不先改代码 |
| 端口 80 无法访问 | Nginx 状态、端口占用、API 是否 healthy |
| API 根路径没有聊天页面 | 8000 提供 API，80 才是工作台 |
| 模型 401/403 | 凭据、权限、额度和兼容接口，不打印 Key |
| Redis NOAUTH/连接拒绝 | 密码一致性、容器与宿主机地址 |
| Chroma 进入嵌入式模式 | 检查服务器地址和数据位置，避免误以为数据丢失 |
| 首次检索慢 | 模型下载、初始化、改写、重排分别计时 |
| 改写或重排 JSON 告警 | 检查模型输出与回退，不能把所有结果视为优化成功 |
| Windows 安装编译失败 | 原生依赖 wheel；优先使用 Linux Docker |
| Render /docs 为 404 | 公网网关有意关闭管理接口，本地仍可用 |

## 11. 最小验收顺序

`docker compose ps` → `/health` → 单轮聊天 → 多轮补充 → 知识搜索 → 混合路由 → 工具轨迹 → Skills → 监控 → 自动化测试 → 预算允许时运行评测。

前端静态页面打开、API 返回 200 和真实模型正确回答是三个不同层次，应分别检查。
