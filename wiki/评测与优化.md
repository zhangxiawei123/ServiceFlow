# ServiceFlow 数据评测与优化

## 目标与口径

优化应回答：改动解决了哪类失败，提升多少，付出多少延迟和费用，是否影响其他能力。没有固定测试集与原始报告时，不写准确率或提升百分比。

区分四类验证：功能单测、数据库集成测试、真实聊天验收、质量/性能实验。四者不能相互替代。

## 1. 数据集设计

意图数据记录 `case_id / message / expected_intent / category / split`；多轮样本额外保存 history。覆盖普通表达、近义表达、否定、短句、噪声、复合诉求、强制转人工和越权请求。

RAG 数据记录问题、gold_doc_ids、参考要点、不可回答标识和文档版本。对话数据记录任务目标、预期动作边界及必要信息。

训练或调参集与最终测试集分离；同一问题的近义改写不能跨集合泄漏。使用脱敏或合成数据，人工复核标签，保留争议样本。

## 2. 现有评测入口

`evaluation/evaluator.py` 提供意图 Accuracy、Macro-F1、各类 Precision/Recall/F1，以及相关性、准确性、完整性、有用性四维 LLM Judge。`/eval/run` 可接受自定义样本：

```json
{
  "intent_cases": [
    {"message": "登录一直报401", "expected_intent": "technical_login"},
    {"message": "退款多久到账", "expected_intent": "refund"}
  ],
  "dialog_cases": [
    {"turns": ["我想退款", "订单号是 #12345", "需要多久到账？"]}
  ]
}
```

默认包含 11 条意图样本、5 组对话，规模只适合冒烟。多轮评测直接调用编排器并构造历史，不完整覆盖 HTTP 网关、Redis/Chroma 记忆及后台画像；这些要另外集成测试。

分类指标需要明确 gold label；Judge 的“准确性”是模型打分，不是人工核验事实正确率。解析失败与兜底分单独统计。

## 3. 指标定义

| 层次 | 建议指标 | 当前边界 |
|---|---|---|
| 分类 | Accuracy、Macro-F1、混淆矩阵 | 已有基础指标，需独立数据集 |
| 检索 | Recall@K、Hit@K、MRR、nDCG | 需要相关文档标注与新增评测脚本 |
| 回答 | 证据一致性、任务覆盖、拒答正确率 | 不能仅依赖同一模型 Judge |
| 工具 | 成功、超时、越权拦截、降级率 | 结合轨迹及故障注入 |
| 性能 | HTTP P50/P95、首响应、并发、错误率 | 当前没有可信线上压测报告 |
| 成本 | 各阶段 Token、请求数、单次费用 | 需新增统一用量采集 |

Recall@K = Top-K 中命中相关文档数 / 全部相关文档数。MRR 使用第一个相关文档排名的倒数。分类 Accuracy 与 RAG Recall 不是同一个概念。

## 4. RAG 消融实验

固定知识快照、问题集、模型、参数和候选预算，比较：

1. 原查询单路向量检索。
2. 原查询加三个改写，合并去重，不重排。
3. 单路检索加重排。
4. 多查询加重排。

记录召回、排序、回答指标、端到端时延、Token 和解析失败率。多次运行并报告样本量与波动，区分热缓存与冷缓存。

并行仅减少可重叠等待，改写与重排仍是额外模型调用。改写是一个请求生成多个文本，不通常等于“三次改写模型请求”；四路召回也不等于四次大模型生成。重排候选不超过 K 时，当前实现会直接返回，不再调用模型。

## 5. 优先改进项

- 改写：限制 JSON 数组元素类型、数量和长度；去空、去重复，保留原始实体，防止查询漂移。
- 去重：以稳定 chunk_id 代替包含 score 的整个结果字符串。
- 重排：校验索引唯一且合法，补齐遗漏；返回实际成功状态，不只显示“尝试过”。
- 切片：比较句子切分、重叠窗口和按标题分层；增加来源与版本。
- 成本：简单问题跳过扩展；复用安全的检索结果；按延迟预算选择候选和模型。
- 记忆：评估摘要遗漏、串用户、跨会话污染和删除策略。
- 可靠性：增加故障注入、熔断单探针测试、后台任务可靠队列。

以上是优化路线，不是已经实现或已测得提升的结论。

## 6. 回归与基线

保存 commit、数据集哈希、模型版本、提示词及运行参数。现有评测器能与上次报告比较相对下降超过 5% 的指标，并把本次结果写为新基线。

自动滚动基线可能逐步接受退化，正式实验应另外保留不可变的审核基线，不能只依赖会被覆盖的本地文件。

## 7. 交付证据

每项结论应能链接到脱敏数据、命令、原始结果、汇总脚本和失败案例。当前仓库不宣称“约 500 条自建样本”“91.3% 准确率”“召回提升 40%”等没有报告支撑的数字。

记录格式见[指标模板](指标记录模板.md)，功能检查见[验收清单](验收清单.md)。
