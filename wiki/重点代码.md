# ServiceFlow 重点代码阅读指南

按一次请求经过的边界阅读，不需要先背完整源码。

| 顺序 | 文件与符号 | 阅读目标 |
|---|---|---|
| 1 | `api/main.py: lifespan / chat` | 依赖初始化、记忆读取、意图分析、响应与后台画像 |
| 2 | `core/llm_config.py: load_llm_config` | 模型 Key、地址和旧变量兼容，不在代码写密钥 |
| 3 | `core/intent_recognizer.py: IntentRecognizer` | 并发识别、融合、实体、低置信度路径 |
| 4 | `agents/agent_orchestrator.py: RoutingDecision / AgentOrchestrator` | 路由、并行、降级与 trace |
| 5 | `agents/agent_orchestrator.py: BaseAgent / ResponseComposer` | 角色提示词、tool-use 循环和结果合成 |
| 6 | `agents/tools.py` | 可执行工具的边界及 Schema |
| 7 | `mcp/tool_manager.py` | 调用、缓存、熔断、查询改写与重排 |
| 8 | `mcp/knowledge_base.py` | 文档导入、切片、向量查询与嵌入式回退 |
| 9 | `memory/conversation_memory.py` | Redis 消息、压缩、情景检索及画像 |
| 10 | `core/skill_loader.py` | 发现规则文件、匹配、截断及热加载 |
| 11 | `monitor/performance_monitor.py` | 指标阈值、异常检测和路由反馈 |
| 12 | `evaluation/evaluator.py` | 分类指标、Judge、基线与回归判断 |
| 13 | `deploy/demo_gateway.py` | 登录、Cookie、同源检查与受限路由 |
| 14 | `frontend/app.js` | 用户标识、会话、发送、状态与轨迹展示 |

## 阅读主链路时回答四个问题

1. 数据从哪里来？请求、记忆、知识库、模型结果不能混淆。
2. 哪里可能失败？区分解析、鉴权、网络、数据库和模型失败。
3. 失败后返回什么？不能用成功状态掩盖未完成业务。
4. 如何验证？找到对应测试、轨迹或可复查的运行结果。

## 容易读错的地方

- `_build_knowledge_context` 在文件中存在，但不是当前 `/chat` 的固定前置调用；聊天检索由共享工具执行。
- `MCPToolManager` 的名字不证明使用了外部 MCP 协议。
- 工具 `compare_amounts` 是算术，不是支付账本查询。
- `create_handoff_summary` 是摘要，不是工单写入。
- 意图向量与知识向量是两条不同路径，不应共用一套“模型语义 embedding”解释。
- `asyncio.create_task` 不是可靠任务队列，`to_thread` 也不是多进程计算。
- `score = 1 - distance` 是展示转换，不是统一校准的相关概率；底层索引距离需明确配置后再比较。
- 工具轨迹主要保存在内存中，不是完整的持久化审计。

## 调试示例

发送混合问题后保留 `request_id`，查 `/trace/tool/{request_id}`，再对照 `routing_reason` 和实际工具。路由错误先看分类及领域评分，检索错误先看查询与候选，回复错误再看证据和提示词，不要一律归因于模型能力。

对应知识与优化问题见[开发手册](ServiceFlow开发手册.md)。
