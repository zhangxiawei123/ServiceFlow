# ServiceFlow 业务流程说明

## 1. 接收请求与读取记忆

`POST /chat` 接收 `message`、`user_id` 和可选 `conv_id`。没有会话 ID 时后端生成。请求经公网演示网关时，先进行鉴权、体积、频率和并发检查；本地 API 不经过该网关。

`MemoryManager.get_context` 读取 Redis 近期消息与摘要，并检索 Chroma 情景记忆及画像。历史片段按用户限定范围，优先同会话，不足时可补充同用户其他会话，去重后限制数量。

用户 ID 在当前演示中由浏览器生成，不是经过认证的业务身份。查询条件隔离不能代替生产授权。

## 2. 意图分析

API 取最近消息构造 history，调用识别器，获得细粒度意图、意图组、实体、紧急度及置信度。LLM 和向量路径并发，规则补充分类与实体信息；模型解析失败时保留降级路径。

当前客户端没有远端 embedding 资源时，意图匹配使用本地字符 n-gram 哈希向量，不等同于 Chroma 的语义模型。

## 3. 选择处理方式

- 低置信度 OTHER：先澄清，避免随意调用工具。
- 单一领域：选择对应专业角色。
- 混合领域：根据意图、关键词和实体评分选择主辅 Agent。
- 高风险或明确转人工：生成升级结果。

路由结果包含选择原因及置信度，便于分析误路由。评分和阈值是启发式策略，不能当成经过校准的概率。

## 4. 角色执行与工具循环

每个 Agent 根据角色契约、已有上下文和命中的 Skills 构造提示词。LLM 可以输出文本或 `tool_use`。

执行前检查工具是否属于角色白名单，并校验输入字段；把结果作为 `tool_result` 送回模型。调用轮次有上限，避免无限工具循环。轨迹记录工具名、结果状态及耗时等信息。

工具只分析当前请求、计算明确金额、生成排障或交接建议。没有真实订单查询和退款执行能力。

## 5. 按需检索知识

聊天通过共享 `search_knowledge_base` 工具进入 RAG，而非无条件执行一个固定的检索前置步骤：

```text
查询 → LLM 生成最多三个不同角度的改写
     → 保留原查询并去重
     → 并行查询同一个知识库
     → 合并候选 → LLM 重排 → Top-K
```

改写失败时只保留原查询；重排失败时保留候选原顺序。状态字段 `knowledge_used` 表示工具曾被使用，不证明回答的每句话都有证据；`reranked` 也不应单独视为模型重排质量验收。

## 6. 并行与回复合成

复合问题对主辅角色使用 `asyncio.gather`。Composer 尝试合成有效回答，失败时使用确定性拼接。并行减少相互独立分支的等待，但不减少它们的计算和 Token 成本。

专业角色失败时可以尝试 General 降级。降级不代表已经完成原始业务动作，仍需清楚提示能力不足。

## 7. 写回与后台任务

用户消息和最终回复写入 Redis。消息累计达到压缩阈值时，生成摘要并保留近期消息；摘要可形成 Chroma 情景记忆。

画像通过异步任务更新，使用稳定用户文档 ID 的 upsert。响应完成不表示后台画像已经完成；进程退出可能中断该任务。生产应使用可靠队列、重试和幂等。

## 8. 观测和后续评测

编排器保存最近请求的工具轨迹，Monitor 定期读取统计并生成告警及路由惩罚。这些状态主要在进程内，重启后可能丢失。

离线评测由 `/eval/run` 独立触发，不是每次聊天自动运行。评测会调用模型并产生费用，公网演示禁止访问该接口。

## 场景验收

| 场景 | 应检查的证据 |
|---|---|
| 问候 | 不应无意义地执行昂贵工具 |
| 登录 401 | 技术角色、缺失信息与安全排查建议 |
| 退款到账 | 知识工具与文档内容一致，不承诺真实退款 |
| 登录与重复扣款 | 主辅角色、两类诉求覆盖和合成回复 |
| 补充订单信息 | 同一用户与会话，能够使用近期上下文 |
| 转人工 | 升级标识与摘要，不虚构工单已提交 |
